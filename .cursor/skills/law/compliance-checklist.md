# 脱敏合规检查清单

在交付脱敏结果或合并规则变更前，逐项确认。

## 处理前

- [ ] 明确数据使用目的（内部分析 / 对外交付 / 科研共享）
- [ ] 确认数据使用协议或合同中的脱敏要求
- [ ] 确认输入 PDF 为文本型（可复制文字），非扫描件

## 脱敏范围

- [ ] 所有直接识别个人的字段已擦除（姓名、证件号、联系方式等）
- [ ] 业务要求保留的字段未被误删
- [ ] 仅擦除值，标签完整保留
- [ ] 脱敏方式不可逆（PDF redaction，非白色文本覆盖）

## 技术验证

- [ ] `python3 -m unittest tests/test_redact_pdf_batch.py` 全部通过
- [ ] 输出 PDF 中敏感值不可搜索（`get_text` 无残留）
- [ ] 批量处理时输出目录结构与输入一致
- [ ] 递归模式下子目录 PDF 均被处理

## 交付前

- [ ] 使用真实样例人工抽查
- [ ] 记录本次脱敏的字段范围与版本（git commit 或变更说明）
- [ ] 原始含个人信息文件未与脱敏文件混放在同一对外目录

## 常见风险

| 风险 | 后果 | 缓解措施 |
|------|------|----------|
| 规则过宽 | 误删业务数据 | 用 `FIELD_STOP_PATTERN` 限制匹配边界 |
| 规则过窄 | 个人信息泄露 | 对照字段清单逐项测试 |
| 扫描 PDF | 脱敏无效 | 先 OCR 或拒绝处理并提示用户 |
| 仅视觉遮盖 | 文字仍可复制 | 必须使用 `apply_redactions()` |
